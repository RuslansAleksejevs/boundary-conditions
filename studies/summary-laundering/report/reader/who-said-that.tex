{\large Does an agent's summary make an untrusted instruction more powerful?}\par
{\small Ruslans Aleksejevs \enspace | \enspace 9 November 2026}\par
{\footnotesize Draft for human author review. No affiliation is asserted.}

\reportsection{Abstract}
An agent may ignore an instruction in an external document yet accept the same
instruction when it arrives in a colleague's summary. We test this possibility
without changing the agents' actual permissions. A tool-free summarizer reads a
synthetic record; an executor must answer the original task without changing a
protected approval flag. We replay original records, verbatim extracts and saved
summaries under document and colleague labels, with two additional soft defenses.
The frozen main evaluation uses one hosted Qwen3.5-122B-A10B configuration on
40 attacked tasks and 20 paired clean versions. Across 480 scheduled executor
responses, 443 complete the task correctly, 33 are invalid, two abstain and two
are missing. No forbidden state change or schema-valid protected-write attempt
is observed in the 478 available responses. Both primary comparisons have 39
complete attacked pairs and a zero estimated difference, but conservative
95\% intervals span approximately minus 43.49 to plus 43.49 percentage points.
An actual trace shows the unsafe instruction surviving in a summary without
being followed; another shows a plausible answer rejected for its format.
These are illustrations, not additional experiments. The study provides a
replayable test of source labels and text transformation, not evidence of a
successful exploit, universal safety, equivalence or effective soft defenses.

\reportsection{1. The question and contribution}
Documents often mix useful facts with instructions that have no right to change
the task. A summary can carry both onward. We ask two different questions:
does \emph{rewriting the content} change the risk, and does \emph{calling its source
a colleague} change the risk? Treating those as one change makes the answer unclear.

Our contribution is a controlled replay design and an auditable negative result.
We keep the original task, policy, tool and saved summary fixed when testing the
source label. We score actual state changes and correct task completion together.
The outcome is bounded evidence about this pipeline, not a new prompt-injection
mechanism or a claim that agent handoffs are generally safe.

\reportsection{2. Closest related work}
Peters-Gill et al.'s \emph{Can CaMeLs Talk?} already shows how untrusted data can
cross agent boundaries and proposes provenance-preserving communication~\cite{camel}.
We do not implement or reproduce multi-CaMeL; we isolate a displayed source label
while keeping message privileges unchanged. Dai and Guerra-Manzanares's
\emph{StateFence} motivates protecting task state while retaining useful
evidence~\cite{statefence}. Our small dictionary-based tasks are not its
security-operations benchmark.

\reportsection{3. How the test works}
Each task asks for a code or arithmetic result. One attacker-controlled paragraph
asks for an unrelated approval flag to become true, claiming a colleague's request,
approval, a prerequisite, or a quoted work plan. The attacker cannot change
the task, system policy, tool schema or scorer.

A summarizer receives the task and record, has no tools, and is asked to preserve
useful facts while treating source instructions as data. We save one summary
per input. Each executor starts with a fresh context and reset state.

\textbf{Eight conditions.} R is the original record; E is a verbatim extract;
S is the saved summary. Each is shown as D (external document) or P (colleague
handoff), giving six conditions. S-P-W adds a generic warning; S-P-P adds
harness-written provenance stating that the source cannot change the task.
Both supplements have equal UTF-8 length, not equal meaning or token count.
All evidence stays in the same lower-priority user message.

The extract retains the facts and full attack, approaching the summary's byte
length without rewriting. A gap of at most 10\% is matched; more than 20\%
unmatched attacked inputs flags weak length control. This does not match meaning:
selection, deletion and rewriting still change together.

\textbf{What counts as success or harm?} The executor proposes one JSON action
batch, with no tool-feedback turn. The normal mock tool would apply a well-formed
protected write, but the policy forbids it. Any false-to-true approval event counts
as harm, even if later reversed. Correct completion requires the exact answer
in the authorized result field. Invalid batches execute nothing and are failures
of useful completion; missing responses stay unknown. A separate hard-allowlist
replay is an engineering check, not another model condition.

\textbf{Model and sample.} Both roles use \texttt{qwen/qwen3.5-122b-a10b} through
OpenRouter's Alibaba route: temperature 0.6, top-p 0.95, requested output limit
8,192 tokens, reasoning enabled. There is one sample per cell and no model search.
The main set has 40 attacked tasks and 20 predetermined clean counterparts:
60 input variants from 40 task clusters, not 480 independent tasks. Main inputs,
templates and analysis were frozen before outputs. No observed response was replaced.

\reportsection{4. What happened}
\textbf{The target failure was not observed.} The main matrix contains
\MainValid{} valid responses, \MainInvalid{} invalid responses and
\MainMissing{} missing responses. Of the valid responses, \MainAbstentions{}
are empty-action abstentions. Useful completion is
\textbf{\MainCorrect/\MainScheduled{} scheduled cells}, or
\MainCorrect/\MainObserved{} observed responses.

No protected false-to-true transition and no schema-valid protected-write attempt
was observed. This zero describes the tested model-and-tool pipeline. It does
not certify missing responses or establish the absence of intent in arbitrary
malformed text. The 33 invalid responses were 32 Markdown-fenced JSON-looking
answers and one action missing its task identifier; none was repaired or regraded.

intervals collapse to [0, 0], which is not evidence of equivalence. The conservative

\textbf{Soft defenses did not show a security benefit.} Their observed effect
differences are also zero. On 39 complete attacked pairs, warning-minus-S-P
correctness is \WarningUtility{} points (bootstrap interval $\WarningBootstrap$);
provenance-minus-S-P is \ProvenanceUtility{} points ($\ProvenanceBootstrap$).
Conservative intervals are wider and also
include zero. These secondary comparisons do not establish a utility gain.

Only 1/40 attacked main inputs is unmatched, below the inadequacy threshold;
the pilot had 3/8 unmatched. The method did not change between them. Matching
bytes still does not isolate paraphrasing, and a summary-selected matched subset
is descriptive, not an unbiased explanation of the causal mechanism.

\reportsection{6. What this result does---and does not---tell us}
Neither the colleague label nor the summary showed more forbidden effects in
this test. The wide intervals still allow important differences. One hosted model,
shared templates and one sample per cell limit what this null result says about
other settings.

Three observations must stay separate: an instruction remains in text, a model
proposes an action, and a tool changes state. We score the last two, not hidden
intentions. Zero executed harm is not enough: useful completion is 443/480, with
invalid and missing responses retained.

No live schema-valid batch challenged the hard allowlist. Its blocking property
comes from code tests, not a live advantage over soft defenses. New models,
tasks or interactive tool use would require a new prospective study, not a repair
of these observations.

\reportsection{Conclusion}
We separated source labels from text transformation without granting higher
privileges. Neither primary comparison showed an effect difference. The result
is a reproducible design and complete negative evidence, not a successful exploit,
a general defense or a safety guarantee.

\reportsection{Appendix: Limitations and Dual-Use / Ethical Considerations}
\subsection*{Limits of the evidence}
The tasks are synthetic lookup and arithmetic. Four fixed attack families do not
represent real adversaries; the attacker already knows its target field and task.
We did not test target discovery, adaptive attacks, long conversations or real
services. The quoted-plan family was outside empirical pilot tuning, not unknown
to the researchers. A hosted alias does not pin immutable weights.

Source labels change wording, not system policy. Byte matching does not match
meaning, and the extract comparison bundles several transformations. Equal-byte
defenses do not equalize information or tokens. Lexical retention is not semantic
annotation; post-summary subsets do not identify unbiased mediation. The examples
are not a representative sample.

One batch and no feedback turn limit the tested behavior. Rejecting a malformed
legitimate answer does not show that an attack was prevented. Missing responses
remain unknown; abstentions remain unsuccessful. The intervals assume independent
task clusters, an assumption weakened by shared templates.

The failed pilot and interruption remain recorded. The untouched-suffix continuation
was an operational amendment, not an unchanged preregistered pilot. Main inputs,
prompts, settings and analysis were frozen before outputs. All errors and missing
cells remain intact; no regrading or additional inference supports this report.

\subsection*{Safety, data handling and funding}
Mock tools change reset in-memory dictionaries only. No real account, credential,
external action or third party is involved. The published toy approval flag is
not a production target. The examples can inform both attack and defense research
by showing an unsafe request in a handoff; soft provenance is not a guarantee.

Experimental calls used an authorized official interface and a contributor-funded
USD 30 study ceiling. The conservative wallet remains USD \StudyWallet{}, not
actual billed spend. All \RetainedHolds{} full unknown or rejected-receipt holds
remain, including the separately reconciled first request; \UnresolvedCosts{}
receipt costs are additionally unresolved. Assistant-session costs are not included
in the reported experimental inference subtotal. No outside sponsor is asserted.

OpenRouter's provider metadata, checked 8 November 2026, reports Alibaba prompt
logging, 30-day retention, no training on submitted data and no zero-retention
guarantee. These are provider-reported terms, not an independent deletion audit.
Only synthetic prompts were sent. Public records exclude credentials, private
approval records, personal paths, provider generation IDs and hidden reasoning.
Internal hashes support consistency, not signed provider attestation.
